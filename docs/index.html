供应商零件资料的可追溯归档与归一化

北美重卡售后零配件 · Django 5.2 + PostgreSQL 最小可运行 Demo

同一个零件在不同供应商、品牌、目录中编号和名称各不相同；编号相似的又可能是不同产品。本项目把供应商的 Excel / PDF / CSV 资料导入为可查询、可核对、可导出、每个字段都能回看原始出处的产品档案，并把拿不准的对应关系交给人工确认。

核心原则：原件只追加不覆盖；每条数据带出处（文件 · 工作表/页 · 行 · 列）；规则只在证据充分且没有任何冲突时自动归一，其余一律进入人工复核并说明理由；人工决定优先于规则、可审计、可回滚。

结果样例

运行 python manage.py demo --with-increment --noinput 后由系统导出的文件（导入供应商 A、B 原始报价表，再导入 A 的新版本和供应商 C 的 PDF 目录）：

文件内容
master_data.xlsx主数据：归一产品、成员条目（各品牌号）、字段级来源
supplier_offers.xlsx供应商报价：同一产品不同供应商分别保留，含历史报价
review_list.xlsx待人工确认清单：疑似重复（触发原因、冲突字段、缺失信息、建议动作）与记录异常；可填写后回写
import_report.xlsx导入报告：每个批次的新增 / 更新 / 冲突 / 未变 / 本次未出现

快速开始

uv sync
cp .env.example .env            # 填写 DATABASE_URL
uv run python manage.py migrate
uv run python manage.py demo --with-increment --noinput --reviewer reviewer --password 你的密码
uv run python manage.py runserver   # http://127.0.0.1:8000/

服务器上可直接 docker compose up -d（包含 PostgreSQL 与 Web 服务），详见 部署。
