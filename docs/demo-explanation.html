零件资料归一化：演示说明

把供应商 Excel / CSV / PDF 变成可查询、可核对、可导出，并且每个字段能追回原始出处的产品档案。

设计原则：原件只追加不覆盖；证据不足时宁可待确认，绝不贸然合并；人工判断优先、可审计，新增资料可持续增量维护。

可追溯文件 · 页/工作表 · 行 · 列
可解释原因码、冲突、缺失、置信度
可持续增量导入、规则重跑、离线回写

1. 数据模型：证据、档案、判断三层

将“事实”和“判断”分开保存：原始资料永远保留，归一产品可以按规则重算，人工决定则单独形成审计记录。

2. 处理流程：先预览，后入库，再匹配

1. 上传xlsx / csv / pdf
2. 归档sha256 原件
3. 提取表格与定位
4. 映射表头 → 语义列
5. 归一类别、车型、尺寸
6. 增量新/变/冲突
7. 匹配自动或复核

3. 匹配规则、置信度与人工复核

候选只在共同 OE、同类别同车型、或同尺寸的记录中产生；名称相似仅是弱证据，编号字符串相似本身不作为合并依据。

自动归一

跨供应商 + 共用 OE + 类别、车型（含年份）、位置均一致。包装尺寸是辅助证据，换包装只提示，不阻断。

人工复核

共用 OE 但缺字段/有冲突；无 OE 但属性相近；同供应商两个编号；年份只部分重叠。

规则排除

无共同 OE 且类别、左右位置或适配车型存在硬冲突。保留排除理由，不误合并。

置信度不是自动合并开关。置信度 = 相等字段权重 ÷ 全部适用字段权重；缺失字段计入分母，有硬冲突封顶 0.3。真正的自动条件是“必要证据完整且无冲突”，避免高相似名称或共同包装误导系统。

6. 后续维护：新增资料形成闭环

维护场景标准操作
新供应商或新格式网页上传 → 预览列映射 → 确认导入；命令行可先 import_source 文件 --supplier D --dry-run，再补 column_aliases.yaml 或使用映射文件。
同供应商最新报价 / 目录直接导入，按“供应商 + 规范化编号”产生新增、更新、冲突和本次未出现；增补文件加 --partial，不会误标未出现。
调整规则修改 synonyms.yaml 或 matching.yaml 后提升版本；先运行 run_matching --dry-run 看影响，再正式运行。人工决定在证据未改变时保留。
离线人工确认导出 review_list.xlsx，填写 decision / note，执行 import_review 文件 --reviewer 姓名；整份校验通过才写入。

7. 演示时的讲解路线

从查询结果开始
搜索 OE-VNL-1001，展示同一产品下多家 SKU、报价、图片和来源。
回看原始证据
打开条目详情、字段来源和原始行，下载原文件。
展示风险控制
打开复核队列，对照共同 OE 却类别冲突的候选。
展示持续维护
导入 A v2 或新供应商 C，查看新增、调价、冲突和规则重跑。

演示结论：系统自动处理格式统一、重复文件、增量识别和证据充分的跨供应商合并；涉及冲突、缺失、同供应商重复、传递合并或资料质量异常时，系统给出可解释的待确认项，由人在 Web 或 xlsx 中完成最终判断。
