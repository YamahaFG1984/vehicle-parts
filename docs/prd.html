PRD：供应商零件资料的可追溯归档与归一化

版本 v1.0 · 2026-09-23 · 状态：已评审，进入实施

1. 背景与问题

业务经营北美重卡售后零配件。同一种零件在不同供应商、品牌或目录中使用不同的产品编号、名称和描述；也有编号相似、甚至共用同一个 OE 参考号，但产品类型、适配车型、安装位置或关键规格并不相同的情况。

当前痛点：

  • 查不全：客户报一个编号，很难找到其他供应商对应的品牌号和报价。
  • 合并出错：凭“编号像”“名字像”“尺寸一样”合并，会把左右件、主体与盖子、不同车型的件混在一起，直接导致发错货。
  • 说不清出处：整理后的表格无法回答“这个尺寸是从哪份文件第几行来的”，出现争议时无法核对。
  • 无法持续维护：供应商每次发新报价表，只能重新人工整理，之前的人工判断丢失。

2. 目标与非目标

目标

  1. 导入 Excel / PDF / CSV 资料，提取编号、名称、规格、适配、供应商、报价等信息，原件不可覆盖、每条信息可回看出处。
  2. 识别可能对应同一产品的记录，自动处理证据充分且无冲突的；其余标出冲突、缺失、不确定项，交由人工确认。
  3. 同一产品不同供应商的报价分别保留；支持按任意编号、关键词、品牌、供应商查询。
  4. 导出主数据、供应商报价、待人工确认清单。
  5. 增量导入新资料时，识别新增、更新、冲突、待确认记录，并保留既有人工决定。

非目标（第一版）

  • 精美界面、权限体系细分、多租户。
  • 扫描件 OCR（只支持带文本层的 PDF）；图片识别。
  • 汇率换算与跨币种比价（资料中无汇率，换算会引入新的不确定性）。
  • 基于机器学习的自动匹配（样本量太小、需要可解释，见设计文档取舍）。

3. 用户角色

角色主要诉求使用入口
资料录入员把供应商新文件导入系统，看到这次新增/更新/冲突了什么命令 import_source、Web 上传 /imports/、导入报告
产品复核人逐条判断疑似重复，补充缺失信息，决定可追溯Web 复核队列 /review/、待确认清单 xlsx 回写
采购 / 销售查询者输入任意编号或关键词，看到归一产品下所有品牌号与各家报价Web 搜索 /search/、产品详情页、导出文件
维护者（开发/数据）接入新供应商格式、调整规则、重跑匹配YAML 配置、run_matching、文档

4. 用户故事

  • 作为录入员，我导入“供应商A报价表 v2”，系统告诉我：3 条更新（报价变化）、1 条冲突（尺寸变了且影响已归一的产品）、3 条新增、1 条本次未出现，并且原来的文件和数据都还在。
  • 作为复核人，我看到一条疑似重复：“A-021 与 B-019 共用 OE-SHARED-01，但产品类型为 Front Grille vs Bug Screen，尺寸不同；建议核对 OE 号，默认不合并”，我点“不是同一产品”并写备注；下次重跑规则它不会再出现，除非任一方的资料变了。
  • 作为销售，我搜 OE-VNL-1001 或 B01X，进入同一个归一产品，看到供应商 A 的 A-01-00（42.67 USD，MOQ 2）和供应商 B 的 B01X（46.58 USD，MOQ 5）两条独立报价。
  • 作为复核人，我对某个尺寸有疑问，点开字段来源，看到它来自 候选人材料_供应商A报价表.xlsx · 报价明细 · 第 2 行 · Package Size 列，原值 122 x 75 x 7 cm，并可下载原件。
  • 作为维护者，面对从未见过的供应商文件，我只需在列别名配置里补几个表头别名（或传一个映射文件），就能导入，未识别的列会被列出而不是被悄悄丢掉。

5. 功能需求与验收标准

F1 导入与提取

  • 支持 .xlsx（多工作表、表头不在第一行）、.csv、带文本层的 .pdf（表格，可跨页）。
  • 提取字段：原始编号 / 品牌号 / 供应商编号、名称、类别、位置、适配车型、OE/交叉参考号、包装尺寸、报价、币种、MOQ、报价日期；以及原始文件、工作表或页码、行号、列名。
  • 表头通过可配置的别名自动识别；也可提供显式映射文件。

验收：导入供应商 A（27 行）、B（26 行）全部生成记录；任一字段可查到文件、工作表、行、列与原值；原始文件 sha256 在全流程前后不变；同一文件重复导入被识别为“已导入”，不产生重复数据。

F2 疑似同一产品识别与人工确认

  • 记录分为三类：已确认归一 疑似重复 独立产品 / 待补充。
  • 不得仅凭短编号、尺寸相同、名称相似或共同 OE 号自动合并。
  • 每条疑似重复给出：触发原因、冲突字段（双方取值）、缺失信息、置信度、建议人工动作。
  • 人工可：确认合并 / 判定不同 / 标记待补充；可撤销已确认的归一（拆分）。所有决定记审计日志。

验收：样本数据中 A-001~A-012 与 B-001~B-012 的 12 对自动归一；所有“共用 OE 但类型/左右/尺寸冲突”的记录对不被自动合并并出现在待确认清单中；“尺寸相同但类型不同”（如 A-008 空滤壳 vs A-010 风扇护罩）不被合并；缺字段的记录出现在异常清单。

F3 来源与报价

  • 字段级来源：每个字段值都关联到产生它的原始行与列；历史值保留。
  • 同一产品的不同供应商报价分别保留，价格、币种、MOQ、日期原样保存，不做换算；同一供应商的新报价追加而非覆盖。

F4 查询与导出

  • 按任一编号（供应商编号、品牌号、OE 号，忽略大小写/空格/连字符）、关键词、品牌、供应商查询。
  • 归一产品详情：成员品牌号、属性（含各成员是否一致）、供应商资料及各自报价、字段来源。
  • 导出：主数据、供应商报价、待人工确认清单（含可填写的决定列）、导入报告。

F5 增量导入

  • 以“供应商 + 供应商编号”识别同一条目，判定 新增 / 未变 / 更新（仅报价类字段变化）/ 冲突（关键属性变化）/ 本次未出现。
  • 关键属性变化会重新评估相关匹配；已有人工决定在证据未变时保持有效，证据变化时重新打开并说明原因。

验收：导入演示用的 A v2 与供应商 C 的 PDF 后，导入报告的各类计数与预期一致；A-006 尺寸变化导致原自动归一被重新打开进入复核。

6. 非功能需求

类别要求
可追溯原件按内容哈希归档、只追加；每个字段、报价、匹配决定都能追到原始行和决定人。
幂等与原子同一文件重复导入无副作用；单个导入批次失败则整体回滚，不留半截数据。
错误处理任何无法解析的值都产生可见的异常记录（带定位），不静默丢弃、不猜测填充。
可解释每个自动决定都能说明用了哪条规则、哪个规则版本、哪些证据。
可维护新供应商格式、同义词、规则权重和阈值通过 YAML 调整，无需改代码；规则带版本号。
可部署本地 uv 运行；服务器 docker compose up 一键启动（含 PostgreSQL）。
规模Demo 目标：单文件数千行、全库数万条目内交互秒级；匹配使用分块（blocking）避免全量两两比较。

7. 样本数据分析（风险场景清单）

两份样本各 11 列，列名完全不同但语义一一对应；供应商名称不在表内，只能从文件名得到。样本中刻意包含下列场景，系统需逐一正确处理：

场景样本期望处理
干净对应A-001~A-012 ↔ B-001~B-012：OE、车型、位置、尺寸一致，名称写法不同自动归一，报价分列
共用 OE，类型不同OE-SHARED-01：A-021 Front Grille vs B-019 Bug Screen；OE-CONFLICT-01：A-026 vs B-025（尺寸还相同）疑似，冲突=类别，建议核对 OE，默认不合并
共用 OE，名称相近但不是同件OE-SHARED-02：A-022 Air Filter Housing vs B-020 Air Filter Housing Cap疑似，冲突=类别+尺寸
共用 OE，左右冲突OE-SHARED-03（A-023 左 vs B-021 右）、OE-CONFLICT-02（A-027 左 vs B-026 右，且 B 名称未写左右）、OE-VN-1010（A-012/B-012 左 vs B-013 右）疑似，冲突=位置
尺寸相同，类型不同A-008 Air Filter Housing 与 A-010 Fan Shroud 均为 121x22x92；B-022 Bug Screen 与 Century Front Grille 同尺寸；左右侧格栅同尺寸自动排除（不进人工队列，但可查）
无 OE，仅属性一致A-013~A-020、B-014~B-017 与前序记录；同供应商内部也存在疑似，原因=无 OE 属性一致 / 同供应商疑似重复
信息不全的相似件B-018 Right Side Grille VN 65x55x36 与 B-013 Right Side Grille “Volvo VN”（无年份、无尺寸）疑似，同供应商 + 缺关键字段，交人工判断
缺字段A-024/B-022 缺价格币种；A-025 缺车型尺寸 OE；B-023 缺车型；B-024 缺 MOQ；B-013 缺尺寸、车型不完整异常清单；缺关键信息的不参与自动归一
短编号巧合A-01-00 与 B01X 数字部分前 12 行恰好对上，之后错位（A-40-L vs B41R）编号数字从不作为匹配依据
多币种USD、EUR、GBP 混合原样保留，不换算不比价

题目提到 PDF，但样本只有 Excel；面试现场的新资料可能是 PDF 或表头写法不同的 Excel。因此列识别必须基于别名配置且可覆盖，PDF 提取失败必须显式报告。

8. 结果分类口径

分类条件后续
已确认归一规则自动确认（跨供应商、共用 OE，且类别、位置、车型、尺寸全部存在且一致、无任何冲突），或人工确认合并可人工撤销（拆分）
疑似重复有候选关系但证据不足或存在冲突进入待确认清单，附原因、冲突、缺失、建议动作
独立产品没有任何待决候选—
待补充缺少关键字段（类别无法识别、车型/尺寸缺失、价格缺失等）进入异常清单，补资料后重新导入

9. 成功指标

  • 误合并 = 0：样本中所有冲突对都不会被自动合并（由自动化测试守护）。
  • 来源覆盖率 = 100%：每个字段值、每条报价都有来源定位。
  • 重复导入零副作用；增量导入分类准确。
  • 面试现场新文件：从拿到文件到导出结果，只需补充列别名（如需要）并运行一条命令。

10. 范围外与后续路线

  • OCR 与非表格 PDF 的版面解析；LLM 辅助提取（作为候选值，仍需人工确认）。
  • 汇率表与按日期换算；报价有效期。
  • 细粒度权限（录入 / 复核 / 只读）、复核双人确认。
  • 基于历史人工决定训练的匹配打分（在积累足够决定后，作为规则之外的辅助信号）。
